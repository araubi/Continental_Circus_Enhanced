# Continental Circus Enhanced から得た知見

ほかの MSX ゲーム、特にテープで出た Spectrum からの移植作品に役立ちそうなことをまとめました。

## 1. テープから MegaROM へ

1. **RAM をまるごと ROM に。** 読み込み終わったゲームの状態（64 KB）をバンク 1-8 に、VRAM をバンク 9-10 に保存します。バンク 0 の起動コードがすべてを RAM にコピーしてゲームに飛びます。その後のテープ読み込み（ここではサーキット）は、そのバンクからの `ldir` に置き換えます。空いたバンクはエンディング画面などの追加要素に使えます。
2. **ローダーは不要になる：** テープローダーの場所（FB03h）は、常駐させるフックを置くのにちょうどよい場所です。

## 2. 高速化

1. **約束する前に測る。** 速度の見積もりのうち 2 つ（MSX2 でのより速い転送と、アスファルトの省略）は、測ってみると外れでした。
2. **MSX1 の限界は VDP：** 画面表示中で 1 バイトあたり約 29 サイクル。バッファがライン単位、VRAM がセル単位なら、MSX2 でもこのループは短くなりません。
3. **turbo R はほぼ無料：** 起動時に `(002Dh) ≥ 3` なら `ld a,81h / call 0180h`（CHGCPU：R800 の ROM モード）。
4. **フレーム単位のタイマー：** 割り込みで時間を数えるゲームを速くするときは、難易度が変わらないようにタイマーをフレームに結びつけます。ここでは 1 フレームあたりの TIME（十分の一秒）で測り、1.050、オリジナルは 1.045-1.050 でした。

## 3. openMSX の `.omr` リプレイで不具合を再現する

1. `omr_extrae.py` が各スナップショットから RAM、VRAM、VDP と Z80 のレジスタ、キーマトリクスを取り出します。
2. `omr_a_tcl.py N` が `rest.tcl` を作ります。C-BIOS と ROM で起動し、3 秒後に RAM、VRAM、レジスタを書き込みます（`debug write_block "Main RAM"`、`debug write "VDP regs"`、`reg ...`）。続いて押されていたキーを押し、`KeyMatrixState` のイベントを `after time` で予約します。
3. **同じリプレイで修正を試すには、** 復元した RAM の上に新しいコードをコピーします。リプレイには古いコードが入っているからです。
4. **オリジナルのコードでも試す：** 追加した部分（ここではスプライト）を外し、オリジナルでも同じことが起きるか確かめてから、自分のコードの不具合を探します。「遠距離の衝突」はオリジナルのゲームの不具合でした。

## 4. 疑似 3D レースゲームの衝突判定

オリジナルはライバル車の奥行きでの道路座標でライバル車と自車を比べますが、自車は画面の下に描かれます。カーブや坂の頂上では、遠く横の方に見える車と衝突してしまいます。修正：投影ルーチンで求めたライバル車の描画位置が、画面上の自車のカラムに重なることも条件にします。

## 5. ビットマップのゲームでライバル車をスプライトに

- 小さい車：画像ごとに固定のパターン。
- 大きい車：空きスロットの動的パターン。一度に 1 台だけで、シルエットはビットマップに残します。
- 1 ライン 4 枚の制限：大きい車を先に送ります。

## 6. サウンド

- ほかのゲーム（ここではハイパーラリー）の効果音は、ゲームの割り込みの頻度に合わせてフレームをまとめれば使えます。このゲームはほとんど DI で動き、割り込みは毎秒 19 回ほどです。
- 曲はアーケード版のタイミング（曲ごとのティックと単位）に合わせてクオンタイズします。曲を作り直したら、長さのテーブルも作り直します。

## 7. アーケード版から静止画面を作る

- `screen2_desde_imagen.py`：切り抜き、縮小、シャープ化、そして 8x1 の各区間で Lab 色空間の最適な 2 色を選びます（誤差拡散は低め、0.15）。見てわかる絵にはなりますが、手作業での修正がおすすめです。
- `screen2_desde_png.py`：修正した PNG を SCREEN 2 に変換し、3 色以上ある区間を一覧にします。修正を受け取ったら、いくつの区間をどこで直したかを伝えます。
- Spectrum の画面から写した文字は Spectrum の色のままなので、MSX のパレットに置き換えます。

## 8. 実機なしでテストする

- **ジョイスティック：** PSG のレジスタ 14 を読む `in a,(0A2h)` の直後にブレークポイントを置き、`reg a 値`（FFh なし、EFh トリガー、FEh 上、FDh 下）。
- **たどり着きにくい画面：** `reg pc` と入力レジスタでそのルーチンに直接飛びます。

## 9. openMSX の Tcl の落とし穴

- `[debug read_block ... | binary encode hex]` は Tcl ではありません。ブレークポイントのコールバックは **何も言わずに** 失敗します。`[binary encode hex [debug read_block memory アドレス n]]` を使います。
- Python やヒアドキュメントで生成するスクリプトでは、波かっこの中に `\$` を残さないこと。
- ヨーロッパの MSX1 と MSX2 で試すこと：時間で決めたキー入力でも、機種によってはゲームが始まらないことがあり、それは ROM の不具合ではありません。

## 10. R レジスタによる乱数

ゲームは `ld a,r / and 28h` で雨を決めます。`ld a,r` を探すのが、ランダムな判定を見つけるいちばんの近道です。
